# Grok · Flow 생성 시험 기능

이 빌드는 실서비스 지원 완료판이 아닙니다. 사이트 화면 규칙과 생성 실행기는 구현되어 있으며, 로컬 Chromium 및 실제 Codex Luna high 연결을 검증했습니다. 실계정 8개 경로의 생성 검증은 사용자 로그인·파일 선택·생성 승인이 필요합니다. r3부터 작업 전체 승인으로 반복 승인 없이 진행할 수 있습니다.

## 시작

`Start-HONMOON.cmd`를 실행합니다. media-preview 패키지는 `--media-preview`로 실행되어 `%APPDATA%/HONMOON-Media-Preview`에 별도 프로필을 사용합니다. 기존 HONMOON이나 Codex 브라우저의 쿠키·인증 파일을 복사하지 않습니다. 시험 패키지의 실행 파일을 직접 열어도 별도 프로필을 사용합니다.

1. 설정에서 Codex 로그인을 완료합니다.
2. 주소창에서 `https://grok.com/imagine` 또는 `https://flow.google.com/`을 엽니다. 사이트 로그인·2FA는 직접 진행합니다. Flow는 기존 프로젝트의 전체 미디어 화면으로 들어갑니다.
3. 로그인 모드를 해제하고 작업을 입력합니다. 생성 사이트는 모델을 미지정하면 `gpt-6-luna`, 추론을 미지정하면 `high`를 선택합니다. 사용 가능한 모델 목록에서 지원을 검증하며 자동 대체하지 않습니다.
4. 참조 이미지가 있으면 HONMOON의 `＋ 파일`로 PNG/JPEG/WebP 한 개를 선택합니다. Grok의 기존 결과를 영상으로 바꾸려면 해당 이미지 상세 화면에서 시작합니다. 결과 ID와 편집기 첨부가 일치할 때만 사용하며, 무관한 기존 첨부는 직접 제거합니다.
5. 반복 승인을 줄이려면 **작업 전체 승인 후 시작**에서 사이트·작업·파일·생성 횟수를 확인합니다. 비용을 읽지 못해도 진행하려면 해당 항목도 선택합니다. 전체 승인을 사용하지 않으면 준비 승인 후 최종 생성 승인에서 프롬프트·옵션·파일·비용을 확인합니다. 비용 표시가 없으면 추가 확인이 나옵니다. 결과가 불명확할 때는 다시 생성하지 않습니다.

예: `보라색 정육면체 제품 사진을 이미지로 생성하고 다운로드해. 비율 1:1, 첨부 없음.`

## 도구와 동작

기본 세 도구를 유지합니다. 생성 사이트에서 `browser.observe`는 `workflow: media.generate`, 상태 버전, 규칙 버전, 현재 설정, 비용, 선택 파일 ID를 반환합니다. `browser.execute`는 아래 형식을 받습니다. 파일 경로·임의 코드·직접 승인 인수는 받지 않습니다.

```json
{
  "workflow": "media.generate",
  "state": "observe에서 받은 값",
  "requestId": "unique-once",
  "kind": "image",
  "prompt": "보라색 정육면체 제품 사진",
  "fileIds": [],
  "options": {"aspectRatio": "1:1", "count": 1},
  "download": true
}
```

`kind`는 image/video/image_to_video, 옵션은 model/aspectRatio/resolution/duration/audio/count입니다. 화면에 없는 옵션은 거절합니다. 기본 도구 설명에 있던 단계 실행과는 별도 형식입니다. 생성 사이트에서 원시 버튼 실행으로 생성 승인을 우회할 수 없습니다.

r8에서 Grok 이미지 → 영상 연결 경로를 추가했습니다. `image_to_video`는 이미지 생성 후 해당 결과가 편집기에 첨부되었는지 확인하고 영상으로 변환합니다. **제출 2회**이므로 작업 전체 승인 한도도 2회 이상이어야 합니다. 먼저 만든 이미지의 ID를 저장하며, 두 번째 단계 실패 시 이미지를 자동 재생성하지 않습니다. 모델/길이/해상도/오디오 옵션은 영상 단계에 적용하고 비율은 두 단계에 적용합니다. 마지막 영상만 다운로드합니다.

이미 만들어진 이미지는 `observe`가 반환한 `sourceResultId`와 `kind: video`를 사용합니다. 참조 ID를 임의로 만들거나 추가 파일과 섞을 수 없습니다. Grok 영상의 미지정 해상도는 **480p**입니다. 예: `현재 이미지를 480p, 6초 영상으로 변환하고 다운로드해. 이미지를 새로 생성하지 마.`

Grok의 `blob:` 다운로드는 결과 버튼 클릭 직전에 한 번만 연결합니다. 동일 탭·동일 origin·정확한 결과 ID가 포함된 파일명·실제 파일 형식이 모두 맞아야 완료로 인정합니다. 영상 포스터 이미지만 있는 상태는 영상 완료가 아닙니다. 실제 사이트 영상 생성·다운로드는 별도 실서비스 검증 전까지 시험 지원입니다.

작업 ID 응답은 성공이 아니라 접수된 로컬 작업입니다. 로컬 실행기가 준비·승인·생성 관측·다운로드를 처리합니다. 모델에 주기적인 상태 조회를 요구하지 않습니다. 외부 MCP는 `--toolset compact`를 선택하고 `tasks.status`로 필요할 때 확인합니다. 모델과 high 설정은 외부 클라이언트에서 별도로 선택해야 합니다.

준비 단계 120초, 최종 승인 단계 120초, 생성 관측 10분, 다운로드 60초를 적용합니다. 생성 관측은 처음 30초 2초 간격, 이후 5초 간격입니다. 일반 단계 실행의 10단계·120초 제한은 유지됩니다. 프로필 임대는 기존 15분이며 승인 지연으로 임대가 만료되면 중단합니다.

## 현재 지원 범위와 제한

- 규칙 버전: `2026-09-28.1`. Grok의 이름 있는 contenteditable, Flow의 ProseMirror, radio/menuitemradio, 실제 선택 상태를 처리합니다.
- Flow의 프로젝트 내부 미디어 ID와 원본 다운로드 메뉴를 사용합니다. 업스케일 다운로드는 선택하지 않습니다.
- 파일 입력이 생성 편집기에 연결되었다고 확인되는 경우만 첨부합니다. Flow의 `프롬프트 상자에 소재 추가 → 미디어 업로드` 선택기도 승인한 파일 한 개만 전달합니다. 업로드 후 프롬프트에 자동 첨부되지 않는 화면은 `UPLOAD_NOT_VERIFIED`로 중단합니다.
- Grok은 제출 1회를 보장합니다. 사이트가 한 제출에서 여러 결과를 만들면 단일 결과로 추측하지 않고 결과 확인 필요로 남깁니다. 출력 수 1개 보장은 실서비스 검증 전입니다.
- 별도 모달·캔버스·영상 플레이어에서 결과 다운로드 위치가 달라지는 화면은 `DOWNLOAD_UNAVAILABLE`로 중단할 수 있습니다. 미지원 화면을 성공으로 표시하지 않습니다.
- 시간 초과·재시작·취소 시 이미 사이트에 접수된 생성이 계속될 수 있습니다. 로컬 자동 재실행은 없습니다.
- 생성 결과 식별과 파일 형식 검증은 구현되어 있으나 실서비스 화면 변화와 원격 동시 생성에 대한 신뢰도는 파일럿에서 확인해야 합니다.

## 재현

```powershell
npm test
npm run build
$env:HONMOON_MEDIA_REGRESSION='1'
$env:HONMOON_LUNA_SMOKE='1'
node benchmarks/run-live.cjs
```

위 검사는 **격리된 로컬 페이지**에 대한 검사입니다. HTTPS origin을 테스트 프로필의 로컬 응답으로 대체하며 실서비스 크레딧을 사용하지 않습니다. 실제 Luna 검사는 기존 HONMOON Codex 로그인 홈을 프로세스에 지정해 사용하며 인증 파일을 읽거나 복사하지 않습니다.
