# 작업 묶음 실행기

설정 → **작업 실행 방식 → 작업 묶음 · 실험 기능**에서 활성화합니다. 새 경로의 검증 보고서가 절감·안전 기준을 통과하기 전에는 기본값을 기존 기능 호출로 유지합니다. 사용 중인 앱을 자동으로 종료하거나 설정을 덮어쓰지 않습니다.

## 도구

- `browser.observe({query?, limit?})`: 현재 문서의 기능, 입력 종류, 선택지, 상태 버전. 최초 전체 응답 이후 기능 변경분을 반환합니다. `unchanged`는 기능 목록만 같다는 뜻이며 결과 본문은 상태 버전에 별도로 반영합니다. 목록이 잘리면 이름으로 다시 조회합니다.
- `browser.execute({state, requestId, steps, expect})`: 최대 10단계를 순서대로 실행합니다. 대상은 관측 ID(`b2`) 또는 나중에 나타날 요소의 정확한 `{name, action}`입니다. 완료 조건은 `text/value/exists/download`이며 `text`의 검색 문구는 `value` 필드에 넣습니다.
- `browser.recover({level})`: 실패 이후 접근성 → 제한 DOM → 스크린샷 순서의 동의 기반 복구 관측. 동작을 반복하지 않습니다.

```json
{
  "state": "관측 응답의 상태 버전",
  "requestId": "save-settings-once",
  "steps": [
    {"target": "b2", "action": "fill", "value": "보라색 연구소"},
    {"target": "b3", "action": "select", "value": "1:1"},
    {"target": "b1", "action": "click"}
  ],
  "expect": [{"kind": "text", "value": "저장 완료"}]
}
```

`verified`는 명시된 완료 조건을 관측했다는 뜻입니다. 사이트의 전체 업무 성공을 무조건 의미하지 않습니다. `acknowledged`는 명령 전달만 확인한 상태입니다. `stopped/unknown` 응답의 `completed`, `stoppedAt`, `notRun`과 오류를 확인해야 합니다. 결과가 불명확하면 다른 requestId로 자동 재시도하지 않습니다. 동일 키에 다른 계획은 거절하며, 동일 계획은 기존 결과를 반환합니다.

## 실행 경계

한 번의 묶음 승인에 대상·입력·순서·읽기 조건을 표시합니다. 모든 클릭은 효과가 확인되지 않은 것으로 취급해 실행 직전 별도 승인합니다. 업로드도 별도 전송 승인이 필요합니다. 브라우저 실행기가 승인 대기를 처리하므로 그때마다 모델을 호출하지 않습니다.

문서 변경, 인증 화면, 임대 만료, 사용자 제어권 회수, 취소는 묶음을 중단합니다. 탭·origin·요소 신원·입력값·선택지·파일 내용은 실행 직전에 재검증합니다. 로컬 캐시와 증분 스냅샷은 실행 권한을 대신하지 않습니다. 지원하지 않는 커스텀 컨트롤이나 iframe 내부 요소를 무리하게 추측하지 않고 사용 불가로 반환합니다.

최대 실행 시간은 승인 대기를 포함한 120초입니다. 내려받기 등 완료 조건은 각각 최대 10초 기다리며 전체 120초를 넘지 않습니다. 실행 중인 브라우저 명령이 끊기면 결과 불명확으로 남깁니다. SQLite 실행 기록은 재시작 시 중단 상태로 복구하며 자동 재실행하지 않습니다.

## 문맥과 MCP

새 작업은 새 Codex thread로 시작합니다. 작업창의 ‘이전 결과 이어가기’에서 선택한 작업만 지시·결과·파일 ID를 최대 2,000자로 전달합니다. 기존 도구 로그를 재생하거나 요약 모델을 추가 호출하지 않습니다.

내장 Codex와 MCP가 같은 실행기 및 권한 등록부를 사용합니다. 설정에서 방식을 고른 다음 Codex/Claude/Antigravity 연결 설정을 복사하면 해당 `--toolset`이 포함됩니다. 기존 연결은 다시 복사하거나 직접 인수를 수정해야 합니다.

- `--toolset legacy`: 기존 기능 도구 13개.
- `--toolset compact`: 작업 묶음과 작업 관리 도구 10개.

`capabilities.find/inspect`도 공통 게이트웨이에 등록되어 기존 연결에서 사용할 수 있습니다. 외부 클라이언트는 내부 작업의 기능·상태·산출물 조회와 취소 권한을 가져갈 수 없습니다.

## 비교 재현

```powershell
npm run build
$env:HONMOON_BENCH_MATRIX='1'
$env:HONMOON_BENCH_REPEATS='4'
node benchmarks/run-live.cjs
```

5개 작업 × 3개 구성 × 4회 = 60회입니다. Luna low, 새 문맥, 동일 지시문, 순서 교차, 실제 tokenUsage를 사용합니다. 일반 비교군도 압축·증분 스냅샷과 모델 응답 안의 호출 묶음을 사용할 수 있습니다. 실제 사이트·계정·결제는 포함하지 않습니다. 예비시험 결과와 본 측정 결과는 서로 다른 evidence 폴더에 저장됩니다.
