## 결론

이번 작업 묶음의 HONMOON 입력 토큰 합계는 일반 스냅샷 제어 대비 **94.7% 증가**했습니다. 이는 아래 로컬 작업에 대한 관측값이며, 일반 웹 전체나 Flow/Grok에 대한 보편적 절감률이 아닙니다.

캐시를 뺀 입력도 53,946 → 91,248로 **69.1% 증가**했습니다. 두 방식 모두 6/6 작업을 완료했으므로 이번 표본에서 정확도 개선은 확인하지 못했습니다. 요구한 입력 토큰 40% 감소 목표는 이번 작업 묶음에서 달성하지 못했습니다.

실행 로그에서 일반 방식은 총 35회, HONMOON은 61회 도구를 호출했습니다. HONMOON의 반복적인 list → inspect → invoke → list 흐름은 매 단계마다 모델에게 문맥을 다시 전달하게 합니다. 이 결과는 작은 기능 응답 하나가 저렴하다는 사실만으로 전체 작업도 저렴해지지는 않음을 보여줍니다. 다음 최적화 후보는 승인·현재 대상 재검증을 유지하면서 검색과 상세 조회를 합치고, 실행 응답에 변경분과 성공 근거를 함께 제공하는 것입니다. 이번 측정 중에는 이런 성능 최적화를 적용하지 않았습니다.

## 동일 조건과 비교 범위

- 두 방식 모두 같은 Electron Chromium, agent-browser 0.38.1, 같은 페이지·지시문·모델·추론 설정을 사용했습니다. 매 실행마다 새 탭과 새 ephemeral Codex thread를 사용했습니다.
- 일반 방식: agent-browser의 snapshot -c 접근성 트리와 ref 기반 click/fill/select, 본문 읽기, 다운로드 조회. 상용 Chrome 플러그인이나 스크린샷 기반 제어의 실측은 아닙니다.
- HONMOON: 실제 제품의 기능 도구 정의와 Orchestrator를 그대로 사용했습니다. find/inspect/invoke 및 승인·대상 재검증을 거칩니다. 모델에는 구현 소스가 전달되지 않습니다.
- 등록된 도구 수·설명·권장 절차는 각 방식의 실제 비용이므로 차이를 유지했습니다. 공통 기본 지시문과 사용자 작업 지시문은 같고, 도구 사용법만 다릅니다.
- 첫 반복은 일반→HONMOON, 둘째 반복은 HONMOON→일반 순서로 실행했습니다. 서버 프롬프트 캐시는 강제로 초기화하지 못하므로 캐시 토큰을 별도 표시했습니다.
- 모든 동작은 실험용 loopback 페이지에 한정됩니다. 미리 허용한 로컬 동작은 벤치마크 승인기가 처리했습니다. 사람 승인 대기 시간과 인증·결제·실서비스 비용은 포함하지 않습니다. 제품의 승인 정책은 변경하지 않았습니다.
- 입력값·선택값·클릭 수·다운로드 파일 내용을 별도 검사했습니다. 모델의 완료 메시지만으로 성공을 인정하지 않았습니다.
- 각 조건 표본이 2개여서 통계적 유의성이나 일반화된 정확도 개선을 주장할 수 없습니다. 작은 폼, 24개 자료 목록, 로컬 파일 생성만 포함합니다.
- latency에는 모델·도구 왕복, 로컬 스냅샷 재검증, 고정 검증 대기 약 0.8초가 포함됩니다.

## 준비 단계에서 발견한 문제

1. 기존 code_mode_host=false 설정에서는 최신 Codex의 동적 도구 등록은 성공해도 실제 호출이 되지 않았습니다. 시작 시 도구 호스트를 활성화한 smoke test에서 benchmark_ping 실제 호출을 확인했고 제품 어댑터에 수정했습니다. 셸·외부 브라우저 등은 계속 비활성화되어 있습니다.
2. 일반 비교 어댑터에서 탭 선택 시 agent-browser ref가 초기화되어 Unknown ref가 발생했습니다. 실행 직전 동일 스냅샷을 복구하고 role/name 일치를 검증하도록 수정했습니다. 이 로컬 검증 출력은 모델에 추가하지 않았습니다.
3. 이 두 문제를 가진 예비 실행은 별도 원본 폴더에 보존했습니다. 본 비교에 섞지 않았고, 이후 완료된 모든 실행(실패 포함)은 본 표에 포함합니다. 중단된 예비 턴까지 포함한 계정 전체 소모량을 뜻하지 않습니다.

수정은 소스와 개발 빌드에 반영했습니다. 기존 배포 ZIP을 교체하거나 사용 중인 HONMOON 창을 재시작하지 않았습니다. 빌드 및 단위 테스트 13개가 통과했습니다. 첫 준비 실행은 `evidence/live-agent-2026-09-27T15-48-58-645Z`, ref 복구 전 준비 실행은 `evidence/live-agent-2026-09-27T15-53-21-727Z`에 있습니다.
